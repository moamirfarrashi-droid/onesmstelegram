راه‌اندازی از وب گیت‌هاب
۱. در تلگرام از BotFather یک بات بگیر. در کانال اصلی و کانال تست، آن را
   از بخش Administrators اضافه کن و دسترسی Post Messages بده.
۲. در GitHub یک ریپازیتوری تازه بساز، مثلاً onesms-telegram-bot. اگر
   می‌خواهی محتوا قبل از انتشار قابل دیدن نباشد، Private را انتخاب کن.
   قبل از استفاده منظم در ریپازیتوری خصوصی، سهمیه و تنظیمات هزینه
   GitHub Actions حساب خودت را بررسی کن.
۳. فایل ZIP را Extract کن. داخل گیت‌هاب از Add file > Upload files
   همه فایل‌های استخراج‌شده به‌جز publish.yml را در صفحه اصلی آپلود کن.
   ZIP را به همان شکل داخل گیت‌هاب نریز. Commit changes را بزن.
۴. Add file > Create new file را بزن. در نام فایل این مسیر را وارد کن:
   .github/workflows/publish.yml
   کل متن publish.yml داخل ZIP را در صفحه کپی کن و Commit changes را بزن.
۵. در Settings > Secrets and variables > Actions روی Secrets برو و
   این سه مورد را با New repository secret اضافه کن:
   TELEGRAM_BOT_TOKEN = توکن BotFather
   TELEGRAM_CHANNEL_ID = شناسه کانال اصلی به شکل @username یا -100...
   TELEGRAM_TEST_CHANNEL_ID = شناسه کانال تست جدا به همین شکل
   برای کانال، لینک دعوت t.me/+ استفاده نکن. توکن را در فایل یا پیام ننویس.
۶. Actions > OneSMS 60 Days > Run workflow را باز کن.
   preview / day=1 / slot=0 محتوای متنی هر شش پست و نام فایل عکس را
   در لاگ نشان می‌دهد. test / day=1 / slot=0 هر شش پست را به کانال تست
   می‌فرستد. برای تست یک پست، slot را بین ۱ و ۶ انتخاب کن.
۷. پس از اینکه شش پست را در کانال تست دیدی، در همان Settings بخش
   Variables این موارد را بساز:
   CAMPAIGN_START_DATE = تاریخ میلادی روز اول به وقت تهران، YYYY-MM-DD
   ENABLE_POSTING = true
   برای شروع با شش نوبت کامل، یک تاریخ آینده انتخاب کن.
   اجرای زمان‌بندی‌شده بعد از این تنظیمات به طور خودکار کار می‌کند.

کنترل و پیگیری
• status در Run workflow، تعداد کل و امروز، پست عقب‌افتاده و شناسهٔ
  پیام‌های ارسال‌شدهٔ امروز را در لاگ نشان می‌دهد.
• publish اجرای دستی صف است و در کانال اصلی فقط نخستین پست سررسیدشده
  را می‌فرستد. برای ارسال آزمایشی از test استفاده کن.
• GitHub Actions هر نیم ساعت در بازه انتشار صف را بررسی می‌کند. ساعت‌های
  جدول هدف انتشار هستند. اگر اجرا تأخیر بخورد، در اجرای بعدی نخستین پست
  عقب‌افتاده بررسی می‌شود. سقف کانال اصلی شش پست در روز است و در صورت
  عقب‌افتادگی، تکمیل صف ممکن است بعد از روز شصتم ادامه پیدا کند.
• تاریخ شروع و شناسهٔ مقصد با اولین تلاش انتشار در state.json ذخیره می‌شوند.
  این فایل را GitHub Actions می‌سازد. برای توقف موقت ENABLE_POSTING را false
  کن و برای ادامه دوباره true. فایل state.json را نگه دار تا شماره روز و
  سابقه ارسال حفظ شود. با توقف، پست‌های جاافتاده در صف باقی می‌مانند.
• اگر لاگ از pending گفت، ربات منتظر بررسی همان پیام است. ابتدا وضعیت
  پیام را در کانال و شناسهٔ آن را در لاگ نگاه کن. حذف فایل state.json
  ممکن است سابقه را از بین ببرد و باعث تکرار پست‌های قبلی شود.
• برای کارکردن ثبت سابقه، GitHub Actions باید اجازهٔ نوشتن روی شاخه اصلی
  داشته باشد. اگر لاگ State sync failed نشان داد، مجوز و قوانین شاخه
  را بررسی کن.
• نشانه‌های داخل [کروشه] عمداً بخشی از نمونه‌های آموزشی‌اند.
