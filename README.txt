نسخهٔ سبک برای آپلود از مرورگر
فایل ZIP را Extract کن و فایل‌های داخل آن را در ریشهٔ ریپازیتوری آپلود کن.
اگر آپلود گروهی خطا داد، تصویرهای ۰۱ تا ۳۰ و ۳۱ تا ۶۰ را جداگانه Commit کن.
کد پایتون و posts.json را هم همراه گروه اول یا در یک Commit جدا بفرست.
فایل زمان‌بندی را طبق مرحلهٔ ۳ جداگانه تنظیم کن.

وان‌اس‌ام‌اس | نصب بات تلگرام از صفر روی GitHub
۶۰ روز، ۱۸۰ پست، ۶۰ تصویر. همهٔ فایل‌های مورد نیاز انتشار داخل همین بسته‌اند.

۱. آماده‌سازی ریپازیتوری
   برای نصب در ریپازیتوری موجود، اول در مسیر
   Settings > Secrets and variables > Actions > Variables
   مقدار ENABLE_POSTING را false کن. صبر کن اجرای قبلی در Actions تمام شود.
   اگر می‌خواهی فایل‌های قبلی را پاک کنی، اول از Code > Download ZIP
   یک نسخه از شاخهٔ پیش‌فرض برای خودت نگه دار. خود ریپازیتوری و Secrets
   را نگه دار. اگر services-state.json برای همین کمپین قبلاً ساخته شده، حذفش باعث
   از دست رفتن سابقهٔ ارسال همین کمپین می‌شود. سابقهٔ دورهٔ قبلی در
   state.json است و برای شروع این تقویم لازم نیست.
   برای نصب در ریپازیتوری تازه، یک ریپازیتوری جدا برای تلگرام بساز.
   می‌توانی هنگام ساخت Add a README file را روشن کنی تا شاخهٔ اولیه ایجاد شود.

۲. آپلود فایل‌های اصلی
   ZIP را استخراج کن. در تب Code روی شاخهٔ پیش‌فرض، معمولاً main،
   Add file > Upload files را بزن. این فایل‌ها را از داخل پوشهٔ استخراج‌شده
   انتخاب کن: publish.py، posts.json، هر ۶۰ عکس onesms-day-*.png
   و README.txt. سپس Commit changes را بزن.
   این فایل‌ها باید در ریشهٔ ریپازیتوری کنار هم باشند.

۳. ساخت زمان‌بندی
   اگر فایل زمان‌بندی را پاک کردی یا ریپازیتوری تازه است، در تب Code
   روی Add file > Create new file بزن و در کادر نام، این مسیر کامل را وارد کن:
   .github/workflows/publish.yml
   فایل هم‌مسیر را از پوشهٔ استخراج‌شده با یک ویرایشگر متن باز کن و کل
   محتوای آن را در گیت‌هاب قرار بده. سپس روی شاخهٔ پیش‌فرض Commit کن.
   برای دیدن پوشهٔ .github در صورت نیاز نمایش فایل‌ها و پوشه‌های پنهان
   را فعال کن. اگر فایل زمان‌بندی در همان مسیر به‌جا مانده، با دکمهٔ
   Edit محتوایش را جایگزین کن. اگر زمان‌بندی قبلی فایل دیگری داشت،
   آن را در Actions غیرفعال کن تا فقط زمان‌بندی جدید اجرا شود.

۴. آماده‌سازی کانال‌ها و Secrets
   بات باید در کانال اصلی و کانال تستِ جداگانه اجازهٔ ارسال پیام داشته باشد.
   در Settings > Secrets and variables > Actions > Secrets، سه Secret زیر
   را بررسی کن. اگر از قبل در همین ریپازیتوری تنظیم شده‌اند، از همان‌ها
   استفاده کن. در ریپازیتوری تازه با New repository secret بساز:
   TELEGRAM_BOT_TOKEN          توکن بات
   TELEGRAM_CHANNEL_ID         شناسهٔ کانال اصلی
   TELEGRAM_TEST_CHANNEL_ID    شناسهٔ کانال تست
   برای کانال عمومی می‌توانی از @username و برای کانال خصوصی از شناسهٔ
   عددی استفاده کنی. این بسته شناسهٔ عددی کانال تلگرام را به شکل -100… می‌پذیرد.

۵. پیش‌نمایش و تست
   به Actions > OneSMS Services 60 Days > Run workflow برو و شاخهٔ پیش‌فرض را انتخاب کن.
   بار اول mode=preview و day=1 و slot=0 را بده. متن هر سه پست در لاگ می‌آید.
   بار دوم mode=test و day=1 و slot=0 را بده. هر سه پست به کانال تست می‌روند.
   slot=1 عکس، slot=2 آموزش و slot=3 کاربرد خدمات را انتخاب می‌کند.
   ENABLE_POSTING می‌تواند در تمام این مرحله false بماند.

۶. شروع انتشار خودکار
   در Settings > Secrets and variables > Actions > Variables این موارد را تنظیم کن:
   SERVICE_CAMPAIGN_START_DATE = تاریخ شروع میلادی، با قالب YYYY-MM-DD و به وقت تهران
   ENABLE_POSTING = true
   برای اینکه روز اول هر سه نوبت منتشر شود، یک روز آینده انتخاب کن.
   ساعت‌های هدف به وقت تهران ۱۰:۳۰، ۱۴:۳۰ و ۱۷:۳۰ هستند.
   اولین اجرای موفق انتشار، فایل services-state.json را می‌سازد.
   برای توقف موقت انتشار ENABLE_POSTING را false کن.

اگر مشکلی پیش آمد
- اگر Run workflow را نمی‌بینی، مسیر فایل زمان‌بندی، شاخهٔ پیش‌فرض
  و فعال بودن GitHub Actions را بررسی کن.
- اگر test خطا داد، Secret مربوط، شناسهٔ کانال تست و مجوز ارسال
  بات را بررسی کن.
- اگر لاگ State sync failed نشان داد، امکان نوشتن Actions روی شاخهٔ
  پیش‌فرض را بررسی کن. فایل زمان‌بندی مجوز contents: write را درخواست می‌کند.
- اگر لاگ pending نشان داد، ابتدا خود پست را در کانال بررسی کن.
  فایل سابقه را پاک نکن.
- برای پیگیری از mode=status استفاده کن. اگر GitHub ارسال برنامه‌ریزی‌شده
  را دیر اجرا کند، بات در اجرای بعدی قدیمی‌ترین پست سررسیدشده را بررسی
  می‌کند و حداکثر سه پست در روز می‌فرستد.
